# Languages, SSIDs and home pages

ShareBox ships its Wi-Fi network name (SSID) and its home pages in 41
language codes (the 40 most spoken languages, Chinese in two scripts). This
document describes the data files, the rules the runtime applies, the page
templates and how to add a language. Translation status is tracked in
[`TRANSLATIONS.md`](../TRANSLATIONS.md).

All files live in `recipes-core/sharebox-config/files/`:

```
i18n/
├── languages.txt          shipped languages (installed)
├── ssid-<lang>.txt        generated SSID per language (installed)
├── country-lang.csv       country -> language table (installed)
├── lang-aliases.txt       browser tag -> language code (installed)
├── strings/<lang>.txt     page strings per language (source, not installed)
└── templates/*.html       page templates (source, not installed)
www/
├── style.css              shared stylesheet
└── <lang>/                generated page set, one directory per language
```

`strings/` and `templates/` are developer sources: the recipe only needs to
install the four data files and `www/`. Installing them anyway is harmless
(about 200 kB).

## Language list

`i18n/languages.txt`: one language per line, three tab-separated columns:

```
<code><TAB><ltr|rtl><TAB><native name>
```

Codes are BCP 47 tags as used for the page directories: ISO 639-1 where it
exists, `fil` for Filipino, `zh-Hans` / `zh-Hant` for Chinese. Arabic (`ar`),
Urdu (`ur`), Persian (`fa`) and Pashto (`ps`) are `rtl`. The native name is
shown in the language selector of every page. Order is the order of the
selector (English first, then by number of speakers).

## SSID

The generated SSID is `ShareBox - <slogan>` with the slogan of the language
("Share Freely" in English, "Partagez librement" in French). It is stored,
already complete, in `i18n/ssid-<lang>.txt` (one line, UTF-8).

An SSID is at most 32 bytes. The prefix `ShareBox - ` takes 11, so a slogan
has 21 bytes: about 21 Latin letters, 10 Cyrillic or Arabic letters, 7 CJK,
Indic or Thai code points. When a translation does not fit, the generator does
**not** write `ssid-<lang>.txt`; the runtime then uses `ssid-en.txt` for the
SSID only (the pages stay in the chosen language). Languages in that case are
listed in `TRANSLATIONS.md`.

Runtime rule (implemented by `sharebox-setup`):

1. `ssid=` in `sharebox.conf`, else `SHAREBOX_SSID`, if set: used as is.
2. Else `ssid-<lang>.txt` for the selected language, if it exists.
3. Else `ssid-en.txt`.

## Language selection

1. `lang=` in `sharebox.conf`, else `SHAREBOX_LANG`, if set and listed in
   `languages.txt`.
2. Else, if a country is set (`country=` or `SHAREBOX_COUNTRY`), its entry in
   `country-lang.csv` when not empty.
3. Else `en`.

### Country table

`i18n/country-lang.csv`, header `country,lang`, one line per ISO 3166-1
alpha-2 code (all 249 codes, sorted).

> Rule: `lang` is set only when the country has exactly one official (or de
> facto national) language **and** that language is shipped (a code from
> `languages.txt`). Otherwise it is empty, which means English.

Notes on the choices made:

- De facto single languages count: `US`, `GB`, `AU` → `en`, `MX` → `es`,
  `TW` → `zh-Hant` (Mandarin, traditional script), `CN` → `zh-Hans`.
- Regional co-official languages do not count when the national language is
  single (`ES` → `es`, `NL` → `nl`, `VE` → `es`).
- Countries with several official languages are empty: `BE`, `CH`, `CA`,
  `IN`, `LU`, `SG`, `PH`, `PK`, `KE`, `TZ`, `ZA`, `CM`, `AF`, `HK`, `MO`, `IQ`,
  `MA`, `DZ`, `PY`, `PE`, `BO`, `IE`, `MT`, etc.
- Countries whose 2020s constitutions demoted French to a working language
  (`ML`, `BF`, `NE`) and Ethiopia, which has five federal working languages
  since 2020, are empty.
- Overseas territories follow their administering country's language when it
  is their only official one (`RE`, `NC` → `fr`, `VI` → `en`; `GU`, `PR`,
  `AS` have two official languages and are empty).

The table is data, reviewed at each release; corrections need no code change.

### Browser language

Pages are served under `/<lang>/`. lighttpd chooses the directory from the
`Accept-Language` header when it exists, else the selected language, else
`/en/`. Browsers send tags such as `zh-CN`, `zh-TW`, `pt-BR`, `tl`, which do
not always match a directory: `i18n/lang-aliases.txt` (`alias<TAB>code`,
case-insensitive) maps them. Suggested lookup for each tag: exact directory,
alias table, then both again after removing the last subtag
(`pt-BR` → `pt`, `zh-Hant-TW` → `zh-Hant`).

Only lighttpd images (base, modular, library, full) use these pages. luffy
(classic) and Shareboxx serve their own English interface on port 80; their
engine fragments exist for consistency only.

## Page set and placeholder contract

Each `www/<lang>/` contains:

| File | Kind | Placeholders (replaced by) |
| --- | --- | --- |
| `index.html.in` | page template | `@@ENGINE_LINKS@@` (recipe, build time) |
| `engine-<engine>.html` | fragment | none |
| `how-it-works.html` | final page | none |
| `status.html.in` | page template | `@@CLIENTS@@`, `@@DISK_FREE@@`, `@@VERSION@@`, `@@WARNINGS@@`, `@@UPDATE_RESULT@@`, `@@UPDATE_SECTION@@` (status CGI) |
| `status-update.html.in` | fragment | `@@BUNDLE@@` (status CGI) |
| `status-result-ok.html` | fragment | none |
| `status-result-error.html.in` | fragment | `@@ERROR@@` (status CGI) |

`www/en/index.html` is also committed: `en/index.html.in` with the base
engine fragment, a valid page for the captive portal before the recipe has
assembled anything. The recipe overwrites it with the engine's version.

Engines: `base`, `classic`, `modular`, `shareboxx`, `library`, `full`.

### Home page (build time)

`index.html` = `index.html.in` with the line `@@ENGINE_LINKS@@` replaced by
the content of `engine-${SHAREBOX_ENGINE}.html`, for every language. The
placeholder is alone on its line. Each service card is one `<li>` on one line,
so optional services can be removed with a line filter:

- `optional-forum`: forum card (`/forum/`), remove when Sriracha is not built
  (`sed '/optional-forum/d'`).
- `optional-upload`: upload card (`/files/upload/` in modular, `/upload/` in
  full), remove when uploads are disabled (`upload_max=0`). Since that is a
  run time setting and `/usr` is read-only, the runtime may instead generate
  the pages in `/run/sharebox/www` or ignore it (dufs refuses the upload).

Links per engine:

| Engine | Cards |
| --- | --- |
| `base` | none, an explanatory paragraph |
| `classic` | "Open the ShareBox" → `/` (luffy), note "interface in English" |
| `shareboxx` | "Open the ShareBox" → `/`, notes "in English" and "needs JavaScript" (no non-JS fallback) |
| `modular` | Files `/files/`, Upload `/files/upload/`, Chat `/chat/`, Forum `/forum/` |
| `library` | Library `/wiki/`, Files `/files/` |
| `full` | Library `/wiki/`, Files `/files/`, Upload `/upload/`, Chat `/chat/`, Forum `/forum/` |

### Status page (run time, CGI)

The CGI serving `/status` picks the language from the `lang` query or form
parameter (pages link to `/status?lang=<code>`; the form posts a hidden
`lang`), else from `Accept-Language`, else the selected language. It validates
`lang` against `languages.txt` before using it in a path. It reads
`/usr/share/sharebox/www/<lang>/status.html.in` and replaces:

| Placeholder | Value | Escaping |
| --- | --- | --- |
| `@@CLIENTS@@` | number of associated stations | digits |
| `@@DISK_FREE@@` | free space of `/data`, e.g. `12.4 GB` | HTML-escape |
| `@@VERSION@@` | `DISTRO_VERSION` / RAUC slot version | HTML-escape |
| `@@WARNINGS@@` | zero or more `<li>…</li>`, one per line of `/run/sharebox/warnings`; **empty string when none** (the "No warnings" text is shown by CSS only when the list is empty) | HTML-escape each line |
| `@@UPDATE_RESULT@@` | after a POST: `status-result-ok.html`, or `status-result-error.html.in` with `@@ERROR@@` = RAUC message; otherwise empty | HTML-escape the message |
| `@@UPDATE_SECTION@@` | `status-update.html.in` with `@@BUNDLE@@` = bundle file name, when a verified bundle is pending and `SHAREBOX_UPDATES = "1"`; otherwise empty | HTML-escape |

Every placeholder is alone on its line except `@@CLIENTS@@`, `@@DISK_FREE@@`,
`@@VERSION@@`, `@@WARNINGS@@` and `@@BUNDLE@@`, which are inline. A plain
`sed` with `|` as separator works as long as the values are escaped first.

The update form:

```
POST /status
lang=<code>&bundle=<bundle file name>&action=install
```

The CGI must not trust `bundle`: it only installs the bundle it found and
verified itself, and may use the field to check the user confirmed the same
one.

## Generator

Pages and SSID files are generated from the string tables and templates and
committed. The generator runs on the developer host only (Python 3):

```
scripts/gen-i18n-pages.sh     # generate, then run scripts/check-i18n.sh
scripts/check-i18n.sh         # checks only (POSIX sh, CI)
```

- String tables (`strings/<lang>.txt`): `key=value` per line, `#` comments,
  UTF-8. Values are plain text, HTML-escaped by the generator. Markers
  `{http}`, `{https}`, `{example}` become left-to-right code spans, safe in RTL
  text. Missing keys fall back to English with a warning. For French, the
  generator adds the no-break space before `: ; ? !`.
- Templates (`templates/*.html`): `{{key}}` inserts a string, `{{@lang}}`,
  `{{@dir}}`, `{{@title}}`, `{{@body}}`, `{{@langs}}` and `{{@cur_*}}` are
  computed. `layout.html` wraps `index.html`, `how-it-works.html` and
  `status.html`; the other templates are fragments. `@@...@@` placeholders are
  copied untouched.

`check-i18n.sh` verifies `languages.txt` (format, RTL set), SSID files (one
line, `ShareBox - ` prefix, at most 32 bytes, `ssid-en.txt` present), that
every language has a complete page set with its placeholders and `lang` /
`dir` attributes, `country-lang.csv` (header, two-letter codes, no duplicate,
only shipped languages), `lang-aliases.txt` targets, and HTML well-formedness
with `xmllint --html` when available.

## Pages

- Static HTML and one CSS file, no JavaScript, no cookies, no external
  resource, no web font (system fonts cover every script on current phones).
- Every page has `lang`, `dir`, `<meta charset="utf-8">`, a viewport, a skip
  link and links `/style.css`.
- The stylesheet uses logical properties only (`margin-inline`,
  `border-inline-start`, `inset-inline-start`...), so RTL pages need no
  separate rules, and follows `prefers-color-scheme` for dark mode.
- The footer lists every language with its native name, linking to
  `/<code>/` with `hreflang` and `lang`.

## Adding a language

1. Add a line to `i18n/languages.txt` (code, direction, native name).
2. Copy `i18n/strings/en.txt` to `i18n/strings/<code>.txt` and translate the
   values (keep the keys, the markers and the names ShareBox, PirateBox,
   LibraryBox, JavaScript). Keep `ssid_slogan` at 21 bytes or less if
   possible: `printf '%s' 'slogan' | wc -c`.
3. Run `scripts/gen-i18n-pages.sh` and commit `strings/<code>.txt`, the new
   `www/<code>/`, `ssid-<code>.txt` and the updated pages of every language
   (their language selector changed).
4. Optionally add browser aliases to `lang-aliases.txt` and countries to
   `country-lang.csv`.
5. Add the language to `TRANSLATIONS.md`.

No code or recipe change is needed: the recipe installs whatever directories
exist under `www/` and the runtime reads `languages.txt`.
